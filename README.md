# 지방재정365 사회복지·보건 예산 대시보드

## 대시보드

### **https://beaver21c.github.io/lofin365-expenditure/**

지방자치단체의 사회복지(080)·보건(090) 세출예산을 연도별 추이, 부문 구성,
사업명 검색으로 살펴본다. 시도·시군구를 고르면 그 지역의 예산이 바로 나온다.

> 아직 배포 전이라면 위 주소는 404다. 아래 [처음 준비하기](#처음-준비하기)를
> 한 번 따라 하면 열린다. Pages 를 켠 뒤 실제 주소가 다르면
> `Settings → Pages` 에 표시된 주소로 이 문단을 고친다.

## 무엇을 볼 수 있나

| 화면 | 내용 |
|---|---|
| **추이** | 연도별 예산 꺾은선. 같은 시도 시군구의 **1~3분위 음영**과 중위값을 함께 표시하고, **비교지역을 최대 3곳** 겹쳐 볼 수 있다. 사업 수와 사업당 평균예산도 함께 본다. |
| **구성** | 한 해의 전체 세출 중 사회복지·보건의 비중을 **2겹 도넛**으로, 부문별 크기 순위를 **가로 막대**로 본다. 막대를 누르면 그 부문으로 좁힌 사업 검색으로 넘어간다. |
| **사업 검색** | 세부사업명에 특정 단어가 들어간 사업의 **개수와 예산**을 찾는다. 띄어쓰기를 무시하고("노인 일자리" = "노인일자리"), 제외어도 쓸 수 있다. |

공통으로 되는 것:

- **단위 전환** — 원 · 천원 · 백만원 · 억원 · **%**. 모든 그래프와 표에 함께 적용된다.
  %는 **한 단계 위 항목이 분모**다. 분야(080)를 고르면 전체 세출 대비,
  부문(081)을 고르면 상위 분야(080) 대비가 된다.
- **회계 범위** — 기본은 전체(일반+특별+기금)이고 회계별로 좁힐 수 있다.
- **내보내기** — 그래프마다 **엑셀(.xlsx)** 과 **이미지(PNG)** 버튼이 있다.
  엑셀에는 조회조건·출처·기준일·수집 완전성이 첫 시트로 함께 들어가
  그대로 인용할 수 있다.
- **링크 공유** — 화면 상태가 주소에 담기므로 링크를 그대로 주고받으면 된다.

## 구조

원자료 수집과 대시보드 빌드를 **서로 다른 워크플로로 나눴다.** 집계 방식을
바꿀 때 API 를 다시 호출하지 않아도 되고, 수집은 1년에 한 번만 돌리면 된다.

```
[비공개] lofin365-expenditure-collector
    └ Releases ─ 연도별 원자료 CSV          ← 1. 수집 (연 1회)
                      │
                      │  fine-grained PAT (Contents: Read)
                      ▼
[공개] lofin365-expenditure  ←── 이 저장소
    ├ scripts/aggregate.py                  ← 2. 집계
    └ Actions 아티팩트 → GitHub Pages        ← 3. 배포
```

저장 위치를 셋으로 나눈 데에는 이유가 있다.

| 무엇 | 어디에 | 왜 |
|---|---|---|
| 코드 | git 저장소 | 수백 KB. **영원히 늘지 않는다** |
| 원자료 CSV | 비공개 저장소의 **Releases** | 연도당 87~129MB 라 git 에 넣을 수 없다(파일당 100MB 제한). Releases 는 git 이력에 들어가지 않고 clone 에도 딸려오지 않는다 |
| 대시보드 데이터 | **Actions 아티팩트 → Pages** | 커밋하지 않는다. 커밋하면 git 이 모든 버전을 영구 보관해서 재빌드할 때마다 저장소가 되돌릴 수 없이 불어난다 |

원자료는 비공개로 남고 대시보드만 공개된다.
**API 키는 이 저장소와 대시보드 어디에도 들어가지 않는다** — 수집 워크플로의
Secrets 에만 있고 브라우저는 집계된 결과만 받는다.

## 처음 준비하기

한 번만 하면 된다. 자세한 화면은 [`docs/SETUP.md`](docs/SETUP.md) 에 있다.

1. **토큰 만들기** — 비공개 저장소를 읽을 fine-grained PAT.
   대상 저장소는 원자료 저장소 **하나만**, 권한은 **Contents: Read 하나만** 준다.
2. **Secret 등록** — `Settings → Secrets and variables → Actions` 에
   `SOURCE_REPO_TOKEN` 으로 넣는다.
3. **Pages 켜기** — `Settings → Pages → Source` 를 **GitHub Actions** 로 바꾼다.
4. **측정** — Actions 탭에서 `1. 원자료 측정` 실행. 몇 분이면 끝나고
   결과가 `docs/measurement/MEASUREMENT.md` 에 커밋된다.
5. **빌드** — `2. 대시보드 빌드 및 배포` 실행. 끝나면 위 주소가 열린다.

이후에는 새 연도가 수집됐을 때 5번만 다시 돌리면 된다.
선택할 수 있는 연도·지역·부문은 전부 원자료에서 만들어지므로
데이터가 늘면 화면이 저절로 따라간다.

## 저장소 구성

```
web/                  대시보드 정적 소스 (빌드 때 _site 로 복사)
  index.html
  core.js             적재·집계·분위수·단위 환산
  app.js              화면과 조작
  export.js           엑셀·이미지 내보내기
  style.css
  vendor/             Plotly (직접 포함 — 외부 CDN 에 기대지 않는다)
scripts/
  lofin_common.py     비공개 저장소 접근, CSV 로딩
  measure.py          1단계 측정
  aggregate.py        2단계 집계 → _site 생성
  make_fixture.py     합성 데이터로 화면 확인 (원자료 없이)
.github/workflows/
  measure.yml         1. 원자료 측정
  build.yml           2. 대시보드 빌드 및 배포
docs/
  SETUP.md            준비 절차
  ARCHITECTURE.md     설계 근거와 확인되지 않은 것들
  measurement/        측정 결과 (자동 생성)
```

## 원자료 없이 화면 확인하기

토큰이나 원자료 없이 화면만 보려면 합성 데이터로 만들 수 있다.
숫자는 가짜지만 파일 형식은 실제 빌드 결과와 같다.

```bash
pip install -r requirements.txt
PYTHONPATH=scripts python scripts/make_fixture.py
python -m http.server 8000 --directory _site
# http://localhost:8000
```
