# 준비 절차

한 번만 하면 된다. 5~10분 걸린다.

---

## 1. 토큰 만들기

원자료는 비공개 저장소(`beaver21c/lofin365-expenditure-collector`)의 Releases 에 있다.
워크플로가 기본으로 받는 `GITHUB_TOKEN` 은 **자기 저장소 밖으로 나가지 못하므로**
다른 저장소를 읽을 토큰이 따로 필요하다.

GitHub → 우측 상단 프로필 → **Settings** → 맨 아래 **Developer settings**
→ **Personal access tokens** → **Fine-grained tokens** → **Generate new token**

| 항목 | 값 |
|---|---|
| Token name | `lofin365-dashboard-read` (아무 이름이나) |
| Expiration | 최대 1년. 만료되면 다시 만들어야 한다 |
| Repository access | **Only select repositories** → `lofin365-expenditure-collector` **하나만** |
| Permissions → Repository permissions | **Contents: Read-only** **하나만** |

> **왜 이렇게 좁게 주는가.** 이 토큰은 공개 저장소의 Secrets 에 들어간다.
> 혹시 새어 나가더라도 할 수 있는 일이 *원자료 저장소를 읽는 것*뿐이도록
> 범위를 최소로 둔다. 예전 방식(classic token)의 `repo` 권한은
> **계정의 모든 저장소에 대한 읽기·쓰기**라 절대 쓰지 않는다.

만들면 `github_pat_...` 로 시작하는 문자열이 한 번만 보인다. 복사해 둔다.

## 2. Secret 등록

이 저장소 → **Settings** → **Secrets and variables** → **Actions**
→ **New repository secret**

| 항목 | 값 |
|---|---|
| Name | `SOURCE_REPO_TOKEN` |
| Secret | 1에서 복사한 토큰 |

원자료 저장소가 다른 곳이라면 **Variables** 탭에 `SOURCE_REPO` 를
`소유자/저장소` 형식으로 추가한다. 없으면 기본값을 쓴다.

## 3. Pages 켜기

이 저장소 → **Settings** → **Pages** → **Source** 를 **GitHub Actions** 로 바꾼다.

> 브랜치에서 배포하는 방식을 쓰지 않는 이유가 있다. 대시보드 데이터가 수십 MB인데
> 브랜치에 커밋하면 git 이 모든 버전을 영구 보관한다. 집계를 손볼 때마다
> 저장소가 불어나고, 한 번 커밋된 이력은 히스토리를 다시 쓰지 않는 한 줄일 수 없다.
> Actions 아티팩트로 배포하면 저장소에는 코드만 남는다.

## 4. 측정 실행

**Actions** 탭 → **1. 원자료 측정** → **Run workflow**

원자료 1개년만 내려받아 재므로 몇 분이면 끝난다. 결과는 두 곳에 남는다.

- 실행 요약 화면 (Summary)
- `docs/measurement/MEASUREMENT.md` — 저장소에 커밋된다

여기서 나오는 값이 설계에 남아 있던 추정치를 대체한다.

| 확인하는 것 | 왜 필요한가 |
|---|---|
| 080·090 행 비중 | 검색 파일 크기가 여기서 정해진다 |
| 자치단체 수와 본청 판별 | 분위 밴드의 모집단 |
| 분야·부문 코드 실제 목록 | 화면 구성. 추정하지 않고 데이터에서 뽑는다 |
| 재원 항등식 성립 여부 | 국비/시도비/시군구비 표시가 믿을 만한지 |
| 연도별 실제 완전성 | 수집기가 완전성 0.99 이상을 '완전'으로 기록하므로 최대 1%까지 누락이 숨어 있을 수 있다 |
| 검색 파일 실측 크기 | 추정이 아니라 실제 파일을 만들어 잰다 |

**보고서에서 먼저 볼 것**

- 재원 항등식 불일치율이 **1%를 넘으면** 재원 필드 의미 추정이 틀린 것이다.
  재원 구성 표시는 보류하고 확인이 필요하다.
- 수집률이 **100% 미만인 연도**가 있으면 그 사실이 매니페스트에 실려
  대시보드 하단에 표시된다. 숨기지 않는다.
- 부문이 **12종을 넘으면** 도넛 가독성이 떨어진다. 하위를 묶는 처리를 검토한다.

## 5. 빌드 및 배포

**Actions** 탭 → **2. 대시보드 빌드 및 배포** → **Run workflow**

전 연도를 처리하므로 원자료 다운로드를 포함해 시간이 걸린다.
끝나면 실행 요약에 배포 주소가 나온다.

특정 연도만 다시 만들려면 `years` 입력에 `2024 2025` 처럼 공백으로 넣는다.

## 이후 운영

| 언제 | 무엇을 |
|---|---|
| 새 연도 원자료가 수집됐을 때 | `2. 대시보드 빌드 및 배포` 만 실행 |
| 집계 방식이나 화면을 고쳤을 때 | 같은 워크플로 실행. **원자료를 다시 받지 않는다** |
| 토큰이 만료됐을 때 | 1~2 단계를 다시. 워크플로가 만료를 명확한 메시지로 알려 준다 |

`web/` 이나 `scripts/` 를 `main` 에 push 하면 빌드가 자동으로 돈다.

## 문제가 생겼을 때

**`SOURCE_REPO_TOKEN 없음`**
2단계를 하지 않았다. Secret 이름의 철자를 확인한다.

**`저장소를 찾을 수 없습니다 (404)`**
비공개 저장소는 권한이 없어도 404 로 응답한다. 토큰의
Repository access 에 원자료 저장소가 들어 있는지, Contents: Read 가 있는지 본다.

**`인증이 거부되었습니다 (401/403)`**
토큰이 만료됐을 가능성이 크다. fine-grained PAT 은 최대 1년이다.

**`릴리스 자산을 찾지 못했습니다`**
원자료 저장소에서 수집 워크플로가 아직 실행되지 않았다.

**대시보드가 "데이터가 아직 생성되지 않았습니다" 라고 나온다**
페이지는 배포됐지만 집계 데이터가 없다. 5단계를 실행한다.

**Pages 주소가 404**
`Settings → Pages` 에서 Source 가 **GitHub Actions** 인지, 배포가
성공했는지 확인한다. 첫 배포는 반영까지 1~2분 걸릴 수 있다.
